# SciStudio.ai —— AI 驱动的科学可视化创作平台

SciStudio.ai 是一个基于大模型的「科学可视化 / 仿真创作工作室」，通过对话式交互，帮助科研工作者、教师和创作者快速搭建交互式 2D/3D 可视化、物理仿真和数据仪表盘。  
用户只需用自然语言描述想法，平台就会自动生成可运行的 React 可视化组件并在浏览器中实时展示。

## 一、平台定位

- 面向对象：科研人员、理工科学生、教师、数据分析与科普创作者  
- 核心场景：
  - 物理与天文等学科的交互式演示（如 3D 太阳系、万有引力实验等）
  - 数据分析与实验结果的可视化展示
  - 课堂教学中的动态演示板与交互式教材
  - 科研想法或论文情节的快速可视化原型
- 产品形态：  
  - 基于浏览器的轻量 IDE / 工作室  
  - LLM 驱动的“可视化生成 + 代码编辑 + 作品管理”一体化环境  
  - 结合本地存储与云端快照的创作空间

## 二、项目的实用性

- 自然语言驱动创作  
  - 用户通过聊天式界面输入需求，系统自动规划并生成对应的可视化代码（2D 图表、3D 场景、物理仿真等），降低了科学可视化门槛。

- 可复用的作品管理
  - 使用 `ScienceArtifact` 这一统一结构管理每个作品的标题、描述与代码片段，支持作品列表浏览、新建、删除和切换，便于课堂或报告中快速调用不同示例。

- 本地 + 云端持久化
  - 通过 `localStorage` 持久化作品、消息记录和模型配置，使浏览器刷新后仍能继续创作。
  - 结合 Supabase 云存储（见 `services/cloudStorage.ts`），在不同设备之间同步作品快照，适合在课堂或多终端场景中使用。

- 可直接用于教学与展示
  - 项目内置了多个教学向示例，如：
    - 3D 太阳系运行模拟（行星轨道、相机控制、交互说明等）
    - 万有引力原理可视化（质量、距离与引力大小的联动滑块和力的方向展示）
  - 这些示例可以直接用于课堂演示，也可以作为二次创作的模板。

## 三、项目的创意性

- 将「聊天 + 代码生成 + 3D 可视化」深度结合  
  - Chat 窗口不仅是普通对话，而是驱动一个完整的“规划 → 生成 → 校验 → 修复”流水线。  
  - 模型会根据用户指令和历史对话生成结构化规划信息和可运行组件代码。

- 作品即“科学工件”（ScienceArtifact）
  - 每个作品都被抽象为 `ScienceArtifact`：包含标题、描述、代码和创建时间等元信息。  
  - 这使得作品既像一段可执行的实验代码，又像一个可保存、分享和反复编辑的“科学小作品”。

- 支持多模态与多视图的可视化表达
  - 通过 Recharts 实现传统数据图表，通过 React Three Fiber + Drei 构建 3D 场景，通过 postprocessing 与物理引擎增强视觉表现与仿真真实感。  
  - 模型系统提示中鼓励将同一科学概念拆分为多个视图（3D 场景、图表、文字面板、时间轴等）协同讲解，提升教学与科普的叙事能力。

- 自动错误感知与自修复
  - 运行时如果出现严重错误，渲染层会将错误信息回流给大模型，并触发“自动重试 + 修复”逻辑，在保持科学意图不变的前提下生成更稳健的实现。  
  - 这种“带反馈的代码生成闭环”让非专业前端开发者也能迭代出可用的可视化作品。

## 四、技术栈与技术深度

- 前端框架与工程化
  - 使用 React + TypeScript + Vite 进行开发与构建（见 `package.json` 和 `vite.config.ts`）。  
  - 通过 Error Boundary + 自定义错误处理保证界面在组件级错误时仍可恢复。

- 3D 可视化与物理仿真
  - 基于 `@react-three/fiber`（R3F）和 `three` 实现 WebGL 3D 渲染。  
  - 使用 `@react-three/drei` 提供的辅助组件（如 OrbitControls、Stars、Html 等）降低 3D 交互开发成本。  
  - 集成 `@react-three/rapier` 与 `@react-three/cannon` 等物理引擎，用于构建物理仿真场景。  
  - 利用 `@react-three/postprocessing` 在 EffectComposer 中叠加视觉特效（景深、Bloom 等），营造科幻感与重点突出效果。  
  - 内置 `Sci3D.SceneFromDsl` 能力，可以从高层 DSL 描述自动生成 3D 场景结构。

- 数据可视化与数学表达
  - 使用 Recharts 构建折线图、仪表板等 2D 图表，适合展示实验数据或趋势。  
  - 使用 MathJS 辅助数值计算与公式评估，为物理与数学仿真提供计算基础。  
  - 借助 KaTeX 渲染 LaTeX 形式的数学公式，用于解释科学原理或展示关键方程。

- 大模型集成与多模型配置
  - 使用 `@google/genai` 接入 Gemini 系列模型（如 Gemini 2.5 Flash、Gemini 3 Pro 等）。  
  - 通过自定义 fetch 调用接入智谱 GLM（如 GLM 4.7），使用统一的 `ModelConfig` 描述不同提供方与模型 ID。  
  - 支持在 UI 中选择当前使用的模型、配置不同模型的 API Key，并持久化到本地与云端。  
  - 在 `services/geminiService.ts` 中实现了：
    - 网络重试封装（withNetworkRetry），增强调用稳定性  
    - 规划与代码组合输出的解析（JSON + 代码块）  
    - 将 DSL 描述转换为可运行 React 组件的桥接逻辑  
    - 基于错误和上下文的自动修复流程

- 状态管理与持久化策略
  - 核心应用状态主要通过 React Hooks（useState/useEffect）管理，并在多个维度进行持久化：
    - 作品列表与当前作品 ID  
    - 对话消息历史（按作品 ID 分组存储）  
    - 模型列表、当前选中模型与 API Key 映射  
  - 本地存储结合远端 Supabase 快照（`loadCloudSnapshot` / `saveCloudSnapshot`），形成“本地优先 + 云端备份”的存储模型。

## 五、项目运行方式（简要）

- 开发环境启动
  - 确保本地已安装 Node.js  
  - 安装依赖：
    - `npm install`
  - 启动开发服务器：
    - `npm run dev` （默认端口 3000）

- 构建与预览
  - 生成生产构建：
    - `npm run build`
  - 本地预览构建结果：
    - `npm run preview`

> 提示：本项目依赖的 AI 能力需要在 `.env.local` 中配置对应的 API Key（Gemini / GLM 等），否则在生成作品时会收到相应的错误提示。
